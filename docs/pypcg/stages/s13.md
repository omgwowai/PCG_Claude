# Stage 13 -- LeftOverLots (`PCG_3_2_2_LeftOverLots`, 余地广场与植被)

Python: `Content/Python/pypcg/stages/s13_leftover_lots.py` (the areas, the split, the tiles, the tree points),
`s13_leftover_trees.py` (after the two texture writes), `s13_leftover_plazas.py` (after the five fitting-asset
nodes); shared helpers in `pypcg/geo/ground.py` (`split_ways`, `assign_ways`, `fill_random`, `project_point`,
`volume_overlap`, `difference_binary`) and `pypcg/geo/assets.py` (`index_picks`, the random-range reading);
graph: `pypcg/graphs/s13_leftover_lots.py`; checks: `pypcg/checks/s13.py`; tests:
`Tools/pypcg/tests/test_s13_leftover_lots.py`. Measured on the demo level, 2026-10-19, against the official graph
at component seed 42 (`Tools/pypcg/data/s13_official_measurements.json`, generator
`Content/Python/pypcg_s13_measure.py`).

## 2. The computation

Read from the official IR (`Tools/pypcg/official_ir/PCG_3_2_2_LeftOverLots.json`) and the primitives' own graphs
(exported 2026-10-19 with `PyPCGToolsLibrary.export_graph_ir`). Areas are `geo.areas` (`exclusion`,
`intersection`, `contract`: one subject at a time against the union of the clips, every result polygon its own
item, no sliver filter -- stage 9's rules).

1. **Undividable districts** -- `Subgraph_7` (exact tag), `Subgraph_17` less the central park and the landmark,
   `Subgraph_8` less every Roads area (the whole Roads read: polygons and closed splines, as
   `Compose_Shared_InputsProcessing` takes them). 2 pieces.
2. **Small park** -- `AttributeMathsOp_0` sets the park spline's control points to z 0; `Subgraph_58` intersects it
   with every stage-9 item (their union). 3 pieces.
3. **The split** -- `Subgraph_10 Filter_RandomChoice` (Ratio = `Ratio_Plaza_vs_Trees`, Seed 10, `RandomPerDataset`)
   then `Subgraph_0` (Ratio 0.3, `RandomPerDataset` by default): one Bernoulli per lot each (`geo.keep_each`), NOT a
   count -- none of the stage's eight draws is a `PCGRandomChoice` (`CeilToInt`) count. Plaza side kept by both ->
   plazas and tiles; plaza side unkept -> PUBLISHED (`Reroute_4`); tree side -> trees. Python's own numbers (E2),
   through one `Draws` object (stage 9's design).
4. **The fitting-node areas** -- `Subgraph_13` / `52` / `30` / `21` `Transform_Areas_Contract` (322.886339 cm,
   `UnionBeforeOutputting` FALSE) on the kept plaza lots, `UnderHighway`, `Small Courtyards`, `Medium Courtyards`, in
   each polygon's own `CreatePolygon2D` frame (`geo.areas.in_frame`, trap 64); `Subgraph_9` / `54` / `32` / `25` /
   `37` `Transform_Offset` +30 cm (a polygon's control points move: z + 30); the skirt is NOT contracted. To the
   kept `Subgraph_2` / `53` / `31` / `23` / `38`.
5. **Ground tiles** -- `Subgraph_34 Fill_Areas_Uniformly` (150, NOT grown: unlike stage 10) on each kept plaza lot,
   `Subgraph_48` +15 cm, `Subgraph_49 Custom_Projector_with_rotation_fix`, `Subgraph_59..64` seven ways
   (`geo.ground.split_ways`, the official literal ratios 0.142857 .. 0.5), `Subgraph_65..71` one
   `SM_Plaza_Square_A..G` each with `PositionOffset` (-150, -150, 0) (`geo.ground.assign_ways`), `Gather_1` -> the kept
   `Subgraph_72`. Stage 10's fill, fit, split and assignment, moved into `geo.ground` and shared.
6. **Tree points** -- `Subgraph_24` (the tree-side lots, the unbuildable lots, the cleaned undividable districts --
   its input order -- each less the highway's union), with the small park, `Subgraph_1 Fill_Areas_Randomly` (0.02 /
   m2: `geo.ground.fill_random`, the sampler's non-legacy grid -- cell `sqrt(1e4 / 0.02)` = 707.1 cm, one point per
   cell jittered over the cell less 2 cm, kept when the polygon holds it; Python's numbers), `Subgraph_19` onto the
   terrain -> `TreePoints` -> the native `Subgraph_27` / `28` -> `s13_leftover_trees`.
7. **After the texture writes** (`s13_leftover_trees`) -- `AttributeMathsOp_3/4` roll and pitch 0; `Branch_4`
   (`UseMegaplantsTrees`) -> `Subgraph_26` (eight Black Alder field meshes) or `Subgraph_14` (eight Megaplants):
   `Assign_Assets` with `UseIndexattribute` on `Index` (`geo.assets.index_picks`, 4.4), random rotation (+-2, +-2,
   +-180) and scale (1 +- 0.2, uniform), `Subgraph_26` with `ScaleOffset` 0.7; `Branch_2` -> the kept `Subgraph_76`.
8. **After the fitting nodes** (`s13_leftover_plazas`) -- `Subgraph_20` projects every kit point (its SCALE places
   the projector's three corner probes: `FTransform::TransformVector`, 4.5); `AttributeCast_0` `AssetString`;
   `AttributeFilter_0` birches (`Tree_Birch`, a case-insensitive substring) upright (`AttributeMathsOp_1/2`), less
   those a highway ground tile overlaps (`Subgraph_55` fill 300 on the highway, `Subgraph_57` projection, a miss at
   density 0 removes nothing; `Subgraph_56 Compose_Points_Difference` Discrete / Binary: `geo.ground.difference_binary`
   = the engine's `VolumeOverlap` both ways), then `Branch_3` -> `Subgraph_73` (four Black Alder field meshes,
   `ExtentsScale` (0.7, 1, 1), scale 1 +- 0.2) or `Subgraph_12`; `AttributeFilter_1` drops the `plane` props (its
   Inside has no reader); `AttributeFilter_2/4/5` keep `sidewalk`, `border`, `cone` props as they are; the rest upright
   (`AttributeMathsOp_5/6`); `Gather_2`, `AttributeCast_1`, `Gather_3` -> the kept `Subgraph_74`.

Surface: 135 official nodes, 95 computation by the brief; 93 of them are in Python (21 of those are named
reroutes / reroutes that became edges), 2 stay native (the texture writes).

## 3. Deliberate differences

1. **New random numbers** (spec E2): the split, the cull, the seven tile ways, the tree scatter, the tree
   rotations / scales and the replacement-tree picks are Python's `ctx.rng`.
2. **`Branch_3` / `Branch_4` read the slim graph's own `UseMegaplantsTrees` getter.** Officially `Branch_4`'s getter
   is spelled `UseMegaPlantsTrees` (ruling T4e); on this level nothing reaches it (4.2), so the spelling never acts.
3. **No partition**: `Branch_0/1/2`, `Gather_5`, `Subgraph_77 GridPartition`, `Loop_1` dropped with `Partitioned`.
4. **Published bookkeeping tags** (`Unselected`, `PCG_GridSize_0`, `Type:` / `Primitive:`) are not reproduced; the
   items carry `reservedLots`. Stage 14 filters on none of them (identical result, 6.4).

## 4. What could not be reproduced, and what was found

1. **The official draws themselves** (E2). The published lots are a per-item Bernoulli of 15 reserved lots: the
   official draw publishes 5 lots / 42 099 m2; the port's 199-seed distribution has 2..10 lots, 8 743..95 388 m2, the
   official at its 37th / 38th percentile; the official graph at other component seeds publishes 3..8 lots
   (`Tools/pypcg/data/s13_seed_study.json`). V2's limits for this group are set from that study (6.3).
2. **The texture read stays native -- and the texture does not exist.** `Write_Attribute_fromTexture`'s CoreProcess
   samples `GetTextureData_0` (`bUseAbsoluteTransform`, `ColorChannel` Red, `bUseAdvancedTiling`) under the transform
   `TextureTransform` (Scale 250 000 / 25 000, Translation X 24 373 029.7) composed with the volume's own transform
   (scale / (25, 25, 10)), `SampleTexture_0` per point, the colour remapped from the MERGED set's density range
   (`Normalize`: `AttributeReduce_2/3` min / max) to 0.6..2 (`$scale`) / 1..9 (`index`), the G channel taken. Pure
   Python cannot read the texture's pixels, so both writes stay native between the two Python nodes. But
   `/Game/Textures/Noise/T_CloudNoise_4k` is NOT in this project: `GetTextureData_0` logs "could not be loaded" and
   both writes output nothing -- 6 518 projected tree points reach `Subgraph_27`, none leave it. **Officially the
   demo level has no outer-forest trees** (no `SM_BlackAlder_Field_05_PP` instance; the 515 Black Alder field trees
   are `Subgraph_73`'s birch replacements); the port matches that. A texture with the same role exists as
   `/Game/Textures/Noise/T_Noises_Clouds_4k_`; it is used only in the oracle (4.4), never in a shipped graph.
3. **Zero-area pieces and start vertices of booleans the port computes in world coordinates.** The tree areas
   (`Subgraph_24`) come out 240 pieces against the official 240, 3 degenerate each, the same total area; but the start
   vertex differs on most pieces (official stored local coordinates, s10.md 4.1). They only feed the scatter, whose
   numbers are Python's own, so nothing downstream sees it. Of the in-frame setbacks, 2 of the 62 under-highway,
   2 of the 12 small and 2 of the 31 medium courtyards carry a duplicated collinear vertex placed elsewhere along
   the same straight edge (up to 159 cm; same area to 1e-3 m2): Clipper's near-collinear corner at last-bit frame
   differences (the official ones were contracted from the stored local coordinates, s10.md 4.1). The fitting
   node samples the border per segment, so those six areas may fit differently; not measured per plaza (the
   fitting nodes are kept native and run on the port's polygons).
4. **`UseIndexattribute`, measured** (oracle with the substitute texture on both writes and `Subgraph_26`'s random
   ranges zeroed; `assign_oracle_rows.json` run `s13_index_texture_substitute`): the point's `index` is read as the
   entries' integer `$Index` (truncation); a value naming no entry is UNMATCHED and KEPT (`bKeepUnmatched` defaults
   true) with the attribute's default, the FIRST entry -- indices 8 and 9 (389 points) all took entry 0. All 6 518
   points bit for bit on every field.
5. **The projector's corner probes use the point's scale.** `ResetPointCenter` moves by `TransformVector` (scale,
   then rotation); stage 10's tiles have scale 1 so it never showed. Without it, 1 044 of the 32 108 plaza kit points
   tilted up to 0.25 deg off; with it, all 32 108 match.
6. **The published lots' frame (trap 62, found and FIXED here).** Rewritten through `MakePolygon2DData`, each
   published lot got its own centroid frame; the official ones carry the City's shared polygon transform
   (translation (1 874.36, -1 673.60), yaw -90). Stage 14 contracts and cuts in that frame (trap 64): with the
   port's draws equal to the official ones (seed 7913, found by `Tools/pypcg/s13_seed_study.py`'s method), stage 14
   came out 13 545 against 13 535 (-2 parking lines, -8 arrow decals, vehicles redistributed). **Fix:** the host now
   forwards an input polygon the stage hands back unchanged as the engine's own data object (`convert.read_pin`
   registers each input polygon for the one run, `convert.passed_through`; `Polygon.source` is an opaque key, out of
   equality and records). Then stage 14 is identical mesh for mesh to the official run (6.4). Any stage that returns
   an input polygon unchanged now forwards it the same way (stage 10's `CornerShapes` lots, for one; stage 10 was not
   re-run).

## 5. Corrections to the brief

1. **"Only unbuildable lots"**: `Subgraph_36` filters `LargeBuildingSkirt` (the brief is right); `Subgraph_5`, titled
   the same, filters `unbuildableLots, UnbuildableFootprints` and feeds the TREES, not the plazas.
2. **"tree scales and species from the texture"**: from a texture this project does not have (4.2): officially no tree
   is placed. The port keeps the read native and does the rest in Python.
3. **"the plaza/tree split matches the ratio +-10 %"** is a statement about the share of items over many lots: one
   Bernoulli per lot gives 15 lots a standard deviation of 13 points. The check asserts it from 20 lots up; the test
   on 400 lots at three ratios.
4. **"tree points are on the terrain within 5 cm"**: checked on the flat replay (V1) and offline; the real terrain fit
   is the projector measured point for point (6.2).
5. **"95 in Python"**: 93 are; the two texture writes stay native (4.2).
