## 2. The computation

Every step names the official nodes it replaces. The primitives' rules, read from their own graphs
(`Saved/t16/ir/*.json`, exported with `PyPCGToolsLibrary.export_graph_ir`), are in `geo/areas.py`:

- **`Compose_Areas_Exclusion` / `_Intersection`** = `Polygon2DOperation(Difference / Intersection)`
  in the CoreProcess. The C++ node (`PCGPolygon2DOperation.cpp`) runs ONE input polygon at a time
  against the union of all clips (`ExecutionLoopMode = SinglePrimaryPin`), every result polygon is its
  own data item, and an empty clip pin passes the inputs through. NonZero fill, so holes travel as
  clockwise rings. No sliver filter: the official outputs keep items of 0.0 m2.
- **`Filter_Areas_BySize`** = `FilterDataByAttribute(@data.$area <op> Size x 10 000)`, strict
  (`Greater` default, `Lesser` on the three max filters).
- **`Transform_Areas_Contract`** = `OffsetPolygon2D(-Contract)` (square joins) then, because
  `UnionBeforeOutputting` defaults to true, `Polygon2DOperation(Union)` over all the results.
- **`Filter_RandomChoice`** (ratio mode, `RandomPerDataset` true by default) = one `AttributeNoise`
  draw per data item; `FilterDataByAttribute_0` (default operator `Greater`) sends `random > Ratio` to
  the side `AddTags_1` tags `Unselected`. A per-item Bernoulli keep with probability `Ratio`, not a
  fixed count (`PCGRandomChoice`'s `CeilToInt` count is the OTHER branch, `UseCountInsteadOfRatio`).
  `geo.keep_each`.
- **`FilterPolygonByEdgeLength`** (CitySample, 19 nodes) = the polygon as a closed linear spline,
  `CleanSpline_0` (fuse < 10 cm), `Extract_Segments(CutAngleThreshold 20)`, `AttributeReduce(Min)` of
  the runs' `$Length`, kept when `MinLenght > Threshold`. `areas.min_side` (the 5-degree collinear
  pass is left out; it only straightens a run).
- **`Subdivide_Areas_WithRecursiveSplit`** = `geo.recursive_split` / `geo.auto_split` (stage 6's port,
  reused), with the ratio drawn uniform in [0.5 - c, 0.5 + c], c = `MaxSplitDistancFromCenter` clamped
  to [0.05, 0.45]. Defaults Iterations 2, c 0.3, MinAreaSize 1000.
- **`Subdivide_Areas_withGrid`** with `UseSubdivisionInsteadOfSizes` = `geo.grid_lines(subdiv=...)`:
  `Subdivide_Areas_withGridLoop`'s `Select_0` takes the cell = box / subdivisions (`AttributeMathsOp_3`)
  and `Select_1` the extents = half box + TWO cells (`AttributeMathsOp_5/6`); `CreatePointsGrid` lays
  corners from -extents and `FilterDataByIndex` drops partitions 0 and 1, so the first line lies ON the
  frame box -- which carries the 1 cm vertex boxes, i.e. 1 cm outside the lot, and is clipped away.
  With (1, 2) each large lot gets ONE line, down its middle, parallel to its longest edge. The lot is
  cut with the whole extended line (`Polygon2DOperation_2 CutWithPaths`) and the clipped line
  (`ClipPaths_1`) is published.

The steps:

1. **Lots** -- `Subgraph_0` City - RoadFootprints; `Subgraph_20` (titled "Exclude Landmark and
   Highway") minus `Reroute_1` CentralParkFootprint and `Reroute_2` MainTower -- the highway is NOT
   excluded here. -> `NamedRerouteDeclaration_0 "Lots_1"` -> `Subgraph_17` -> **`Lots`**. The City
   spline enters `Compose_Shared_InputsProcessing`'s `CreatePolygon2D(ForceClosed)` (1 cm
   discretisation, the polyline `convert` reads); the landmark splines likewise.
2. **Prepared lots** -- `Subgraph_5` UndividableDistricts, `Subgraph_8` exclusion, `Subgraph_24`
   minus `Reroute_0` LandmarkPark (110 pieces on the demo level); `Subgraph_3 Filter_RandomChoice`
   (`Ratio` = `PlazaReservationRatio`, `Seed` = `PlazaReservationSeed`, `RandomPerDataset`) ->
   Selected = `NamedRerouteDeclaration_12 "Prepared Lots"`, Unselected = `NamedRerouteDeclaration_1`
   -> `Subgraph_16` -> **`reservedLots`**.
3. **Per class** (`FilterTags_{Small,Medium,Large}Districts` over `NamedRerouteUsage_2`):
   `Intersect_LotsWith{Small,Medium,Large}Districts` (Prepared Lots x the class's districts).
   LARGE only: `Subgraph_57 Subdivide_Areas_withGrid` (SubdivLength 2), its `Subdividing_splines` ->
   `GridSplines` -> the kept `Subgraph_58`, and `Subgraph_59` carves the grammar's `Footprints` out of
   the grid `Areas` (see 3.3). Then `Subgraph_1_*` lot min size (Unselected -> "unbuildable 1") and
   `Subgraph_2_*` lot max size, `Lesser` (Unselected -> "unbuildable 2"); `Gather_0` of the six ->
   `Subgraph_14` -> **`unbuildableLots`**.
4. **Courtyards** (SMALL, MEDIUM) -- `Subgraph_30` / `Subgraph_28` split the lots (Iterations 2,
   c 0.1); `Subgraph_64` / `Subgraph_66` contract the WHOLE lot by 2 000 / 3 000 cm -> `AddTags_1` /
   `AddTags_0` -> **`Small Courtyards`** / **`Medium Courtyards`**; `Subgraph_65` / `Subgraph_67` carve
   the courtyards out of the split pieces.
5. **Highway** -- `Subgraph_7` / `Subgraph_6` / `Subgraph_2` (pieces x highway) -> `AddTags_2` ->
   **`UnderHighway`**; `Subgraph_72` / `Subgraph_73` / `Subgraph_74` (pieces - highway) go on.
6. **Footprints** -- `Subgraph_6_{Small,Medium,Large}District` split (3 / 0.3 / 1000, 1 / 0.3 / 1500,
   2 / 0.2 / 2000); `Subgraph_7_*` footprint min size; `Subgraph_31` / `29` / `32` shortest side over
   300 / 600 / 400 cm. Rejects: `Gather_3` / `2` / `4` -> `Gather_1` -> `Subgraph_13` ->
   **`UnbuildableFootprints`**.
   - SMALL -> `WriteTag_SmallDistricts` -> **`SmallDistrictsBldgFootprints`**.
   - MEDIUM -> `Subgraph_75 Filter_RandomChoice` (0.9, per item) -> `WriteTag_MediumDistricts` ->
     **`MediumDistrictsBldgFootprints`**; its Unselected -> `NamedRerouteDeclaration_9` -> also
     `Subgraph_13` (**`UnbuildableFootprints`**).
   - LARGE -> `Subgraph_68` over 2 500 m2: Selected -> `Subgraph_70` contract 900 cm (union) -> pads;
     Unselected as they are; both -> `WriteTag_LargeDistricts` -> **`LargeDistrictsBldgFootprints`**.
     `Subgraph_25` splits the Selected (2 / 0.05 / 300) and `Subgraph_18` removes the pads ->
     `Subgraph_26` -> **`LargeBuildingSkirt`**.

Surface: 183 nodes officially, 135 computation, 56 of them primitive calls whose own graphs come to
about 2 600 nodes (6 x 171 recursive split, 169 grid, 10 x 29 area filter, 11 x 27 exclusion, 6 x 27
intersection, 3 x 64 edge filter, 2 x 80 random choice, 3 x 26 contract, 8 x 10 tag writes, 79 reroutes /
gathers / tags), about 4 400 with each call's shared input / output templates.

## 3. Deliberate differences

1. **New random numbers** (spec E2): the plaza draw, the six split families and the medium cull are
   Python's `ctx.rng`, through one `Draws` object so a check can substitute the official outcome.
2. **`PlazaReservationSeed` merges into `Seed`** (approved). The stage's `Seed` decides every draw.
3. **The grammar footprint is computed in Python.** `Subgraph_59` officially carves
   `Subgraph_58.Footprints`; the port carves `grammar_bands(lines)` = `path_offset(line, 1000)` (full
   width, butt ends). That is the CoreProcess's own construction for this SGD: `Orientation =
   Horizontal` (probed) sends the splines down `Branch_0 Output B` -> `CleanSpline_1` (a two-point line
   is unchanged) -> `CreatePolygon2D_1 (ForceOpen, Butt, OpenPolygonWidth = Size)`. It saves a second
   Python node after the grammar node. The V1 oracle shows the carved area exact (section 5); the zero-
   area slivers where a band's butt end meets a lot edge differ (official 3, port 8, all < 0.001 m2).
4. **`Subgraph_76` and `Subgraph_62` stay native.** The brief counts them as computation, but they
   move the native grammar node's own points onto the terrain for the native spawner; porting them
   would need a second Python node with a surface input (unrecordable, trap 60). Wired as officially;
   `Branch_2` (Partitioned) is dropped with `Subgraph_11` / `Loop_0`, so `Subgraph_62` feeds `Subgraph_63`.
5. **An empty class or an empty highway selects nothing.** The engine's intersection passes its input
   through when the clip pin is empty, so officially a missing `SmallDistricts` would make EVERY
   prepared lot "small", and a missing highway would put every piece in `UnderHighway`. The port
   intersects only with a non-empty clip, which is what the brief's invariants ask ("the class of each
   footprint matches its lot"; "`UnderHighway` non-empty exactly when a highway crosses"). On the demo
   level every class and the highway are present, so nothing measured depends on it.
6. **The eleven tag writers** (`Subgraph_13/14/16/17/26`, `WriteTag_*`, `AddTags_0/1/2`) are Python:
   each item carries its one contract tag. The bookkeeping tags (`Selected`, `Unselected`,
   `SubdivideAreasWithRecursiveSplit`) are not reproduced; no downstream reader filters on them.
7. **Debug** (`Branch_0/1`, the three category branches, offsets, debug meshes, `Subgraph_4`,
   `Subgraph_9`) is dropped with `debug` / `Debug_DistrictCategories`.

## 4. What could not be reproduced

- **The official draws themselves.** PCG's `AttributeNoise` sequence is not reproduced (E2), and the
  demo's single official draw sits in the tail of the port's distribution for the small class:
  `Small Courtyards` 12 against 13..18 over 99 seeds (median 16). With the official plaza draw
  replayed (V1 oracle), the port gives exactly 12 courtyards, 25 914.03 m2, so the gap is the draw:
  the official one reserved more courtyard-bearing small lots than any of the 99 Python seeds did
  (its reserved COUNT is at the 84th percentile, its area at the 42nd; hitting 6+ of ~18 such lots with
  15 of 110 is a 1.7 % hypergeometric event). Measured on the official graph at other
  `PlazaReservationSeed` values: 12 / 15 / 15 / 15 / 16 / 17 small courtyards at 0 / 1 / 2 / 3 / 500 /
  1000, i.e. the official spread covers the port's 13-18. Seeds 1-3 are not independent of 0: the
  loop seeds each item with `LoopIndex + Seed` (`Filter_RandomChoice_CoreProcessLoop`
  `AttributeMathsOp_0`), so neighbouring seeds reuse shifted values and the reserved count stays 15.
  The V2 rows in `docs/pypcg-v2-thresholds.md` carry this, with the study and the official
  multi-seed numbers in `Tools/pypcg/data/s09_seed_study.json` (generator
  `Content/Python/pypcg_s09_seed_study.py`).
- **Clipper's zero-area slivers** at band ends (3.3): `unbuildableLots` counts +5 items of 0 m2 on the
  official draw, which is part of why that tag's count runs high (median 25-26 vs 21).

## 5. Corrections to the brief

The task brief's invariants are implemented as follows, and the brief should be read this way:

1. **"Outside roads, landmarks, parks and highways by more than 1 m"** is checked as an OVERLAP under
   1 m2. The footprints are made by subtraction, so they touch the road footprint and the highway at
   0 m; a 1 m clearance would fail every lot on the official graph too.
2. **The highway rule applies to the footprints, not to `Lots`.** `Lots` is City - roads - landmark -
   central park (`Subgraph_0`, `Subgraph_20`, whose title says "Highway" but whose inputs are the park
   and the landmark); the highway is taken out per class later (`Subgraph_72/73/74`), and what lies
   under it is published as `UnderHighway`.
3. **The area accounting** is the fuller sum over the PREPARED pieces (Lots less the undividable
   districts and the small landmark park): reservedLots + unbuildableLots + both courtyard tags +
   UnderHighway + every footprint tag (Small / Medium / Large, UnbuildableFootprints,
   LargeBuildingSkirt) + the grammar bands carved from the large lots, within 1 %. The brief's
   "lots + unbuildable + reserved + courtyards" double-counts (`Lots` contains the rest) and leaves
   out the footprints, the highway share and the bands.
