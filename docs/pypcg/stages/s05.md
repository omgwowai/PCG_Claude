# Stage 5 -- CentralParkFootprint (`PCG_2_2_CentralPark_Footprint`)

Contract from `docs/pypcg/stages/s05-brief.md`. Official graph: 3 nodes (excluding input/output) --
one `Create_Spline_Shape` subgraph (52-node CoreProcess), one `PCGMetadataMathsSettings` node that
zeroes `$Position.Z`, and the debug mesh.

## 1. Contract

| | |
|---|---|
| Inputs | none in the official sense; the volume's own transform arrives as one point on the `Volume` pin (`Get Actor Data`, `Mode = GetSinglePoint`) |
| Outputs | `Footprint` -- one closed, linear, 4-vertex spline at Z 0 |
| Parameters | `RectWidth` 100000 (Float), `RectLength` 20000 (Float) -- **new**: the official graph declares no parameter at all |
| Dropped | `Debug_Footprint` (`Debug_PrimitiveData`) |
| Kept generation | none |
| Output tags | the official output carries `Primitive:CreateSplineShape` / `Type:ClosedSpline`; the slim node's output carries `Footprint` |
| Downstream | stage 7 (footprint expansion), 9 (landmark exclusion), 10 (a 500 cm spline-cut buffer expansion), 13 (undividable-district exclusion), 16 (four reads: exclusion, `Place_Point_AtCenter`, `Transform_Outline`, an exclusion), 18 (park exclusion zone) |

## 2. The computation, as numbered steps

1. **Build the rectangle** -- `Park_Footprint` (`Create_Spline_Shape`, overrides `Ngon` 4,
   `Linear` true, `AtWorldOrigin` false, `Width` 100000, `Length` 20000, **no pins wired**). Inside
   `Create_Spline_Shape_CoreProcess` (52 nodes) `Ngon == 4` takes the grid branch, not the sphere
   one: `MakeVectorAttribute_0` makes `(Width, Length, 2)` (`DefaultValue3` 2), `AttributeMathsOp_3`
   multiplies by `(0.5, 0.5, 0)` so `CreatePointsGrid_0`'s extents are `(Width/2, Length/2, 0)`, and
   its `CellCorners` mode with one cell emits the four corners `(+-Width/2, +-Length/2)`.
   `FindConvexHull2D_0` keeps them (order preserved for four convex points).
2. **Parent transform** -- `AttributeTransformOp_2` composes the corners with
   `MakeTransformAttribute_1`: translation and rotation from `GetActorData_1`
   (`GetSinglePoint`), scale from the unconnected `mult` pin, i.e. (1, 1, 1). **The actor's own
   scale (500, 100, 10) is not used** -- the rectangle's size is entirely the node's Width/Length.
   `AtWorldOrigin` false is what makes the actor's transform apply.
3. **Winding** -- `CreateSpline_1` is closed and linear; the corner order after the hull is the
   official one, `(-1, 1), (1, 1), (1, -1), (-1, -1)` in local coordinates, which is a **negative**
   standard shoelace area (traps.md 41). Measured: -2 000 000 000.0000005 cm2.
4. **Zero the Z** -- `AttributeMathsOp_0` (`Operation = Set`, `InputSource1 = $Position.Z`, B left
   on its inline default 0, `pin_defaults[1]` activated with a null value) pins every vertex to
   Z 0. The demo volume sits at Z 9950 and the official output is at Z 0, which confirms the
   default is 0 and that the node runs *after* the parent transform.

So the footprint is `geo.rect(center, RectWidth/2, RectLength/2, yaw)` with the official corner
order, at Z 0: centred on the volume's location, turned by the volume's yaw, sized by the two
parameters only.

## 3. The parameter values: the brief's row is wrong, and measuring says why

The task brief's row says `RectWidth` 16000 / `RectLength` 16000 for stage 5, and its parenthetical
explains that the official graph fixes `Width` 100000 / `Length` 20000 inside the node "so the town
needs them exposed". The two halves do not fit: 16000/16000 is the stage-4 row copied across.

What the demo measures (2026-10-17, `pyg_probe_t13_read.py`): the official park footprint is
**100 000 x 20 000 cm**, 200 000 m2, at (60150, 57100) with yaw 34.222659 degrees -- exactly the
node's own overrides. A slim graph shipping 16000/16000 would publish a 160 x 160 m square,
**-78.7 % on area** against the official, which V2's 10 % area clause would fail outright.

The stage therefore ships the measured numbers:

| parameter | value | source |
|---|---|---|
| `RectWidth` | 100000 | `Park_Footprint` override `Width` 100000 |
| `RectLength` | 20000 | `Park_Footprint` override `Length` 20000 |

They are declared `Float` like stage 4's pair (the official node's override is an integer literal,
but the pin is a Double, and the two stages expose the same pair for the town). The town sets its own
values on the volume anyway (Task 27: 26000 x 9000), so exposing them costs nothing and the demo
default is what reproduces the official output.

## 4. Deliberate differences

1. Two parameters where the official graph has none (section 3). This is the contract's own
   instruction ("the town needs them exposed"), only the default values differ from its row.
2. The output carries `Footprint` instead of the primitive's `Primitive:CreateSplineShape` /
   `Type:ClosedSpline` tags. No downstream stage filters on either.
3. `Debug_Footprint` goes, as the contract says.

## 5. What could not be reproduced

Nothing. The port's four corners equal the official ones to 1.6e-11 cm (the worst of the four,
measured live by `pyg_probe_t13_delta.py`), and the signed areas agree to 5e-7 cm2 of the exact
-2 000 000 000.
