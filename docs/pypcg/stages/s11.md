# Stage 11 -- Buildings (`PCG_3_3_1_Buildings`, 建筑)

Python: `Content/Python/pypcg/stages/s11_buildings_lots.py` (the class split), `s11_buildings.py` (MAIN: heights,
HighRise, terrain fit, the complex-shape split), `s11_buildings_rooftops.py` (tags, rooftop materials); the engine
arithmetic they share in `pypcg/geo/frames.py` (new); graph: `pypcg/graphs/s11_buildings.py`; checks:
`pypcg/checks/s11.py`; tests: `Tools/pypcg/tests/test_s11_buildings.py`. Measured on the demo level, 2026-10-20,
against the official graph at component seed 42 (`Tools/pypcg/data/s11_official_measurements.json`, generators
`Content/Python/pypcg_s11_measure.py` and `Tools/pypcg/s11_measure_offline.py`).

## 2. The computation

Read from the official IR (`Tools/pypcg/official_ir/PCG_3_3_1_Buildings.json`) and the primitives' own graphs
(exported 2026-10-20 to `Saved/graph_dumps/t20/`). Per class c in Small / Medium / Large:

1. **The class split** (`s11_buildings_lots`) -- `FilterTags_*` (`Filter_Tags`, `FilteredInputTags` exact). Each
   footprint is handed back as the object it was read as (`convert.passed_through`), so the native texture write
   sees the official data, frame and stored local vertices (traps.md 68).
2. **The texture height** -- `Subgraph_2_*District`, NATIVE (4.1): `@data.MaxHeight` = the average, over the
   footprint's vertices, of `T_Noises_Grunge_4k_` red remapped to [`MinHeight*`, `MaxHeight*`] (the slim graph's
   getters feed `RemapValueOutLow` / `High` as the official `GetParam_*` do). Read back through an
   `ExtractAttribute` adapter. `DeleteTags_*` (Selected, Unselected) drop with the tags they act on.
3. **Inside the HighRise zones** -- `Subgraph_6` / `42` / `44 Filter_Areas_within_Areas`: per footprint
   (`Polygon2DOperation` Intersection against the union of the zones as `CreatePolygon2D` makes them from the
   closed splines' 1 cm polylines), selected when the first piece's `floor(@data.$area)` equals the footprint's
   own (`include_partially_contained_areas` false).
4. **The HighRise factor** -- `Subgraph_7` / `43` / `45 Write_DistanceFrom` then `AttributeReduce_0/1/2`:
   - the zones' outline sampled by `Write_DistanceFrom_SplineLoop`: `SplineSampler` Distance, `bFitToCurve`, at
     min(100, max(1, length / 100)) cm -- `geo.frames.SplineCurve` reproduces `FSplineCurves` (Hermite segments,
     the 10-step FLOAT reparam table, `CubicInterp`'s float weights) in the spline's local space plus its
     translation (`Spline.frame`, new: the engine adds the translation last, and `c0 + c3 != 1` in floats);
   - each vertex (`ToPoint`: `GetTransformAtDistance(i, 0)`, `Polygon.vertices`, new) to its nearest sample in 3D
     (`PCGDistance` Center/Center, capped at 100 000): the zones sit 246 m up, so every distance is >= 24 611 cm;
   - remapped over ALL the class's selected vertices from [min, max] to [1, 5] (`AttributeRemap`:
     `slope x (v - min) + 1`); the polygon is rebuilt from its points sorted by descending index
     (`CreatePolygon2D_1`), its vertices recomputed through the new frame (`geo.frames.rebuilt_vertices`);
   - `AttributeReduce` is titled "Max HighRise Distance" but its operation is the default, **Average**, computed
     as `sum x float(1 / n)`; the height is multiplied by it (`AttributeMathsOp_0/7/8`). So a footprint's factor
     is 1..5, larger the deeper it sits inside a zone.
   `Gather_0/1/2`: the selected first, then the rest.
5. **The terrain fit** -- `Subgraph_12_* Transform_Project` (positions) then `Subgraph_13_* Transform_Level`
   (Min): the polygon becomes a closed linear spline through its ToPoint vertices, each dropped onto the final
   mesh terrain (`Terrain.height`, exact), then all set to the lowest. Identity transform, control-point
   rotations = the vertices' (`MakeFromXZ(segment, up)` composed with the polygon's frame).
6. **The complex shapes** (Medium / Large, `ComplexBuildingShapes`; `Branch_8` / `Branch_7` Output B):
   - `Subgraph_37` / `34 Filter_Areas_BySize` (> 800 / 500 m2): the levelled spline as `CreatePolygon2D` reads it
     (`ConvertSplineToPolyLine` through the float reparam table -- a zero-length segment collapses to one point --
     the closing point popped, Newell plane, `MakeFromZ`, `operator/=` as a reciprocal multiply:
     `geo.frames.create_polygon_points` / `polygon_frame`), the area of its stored local ring;
   - `Subgraph_35` / `32 FilterSquareShapes`: the polygon's ToPoint vertices as a closed linear spline,
     `CleanSpline` (fuse within 1e-4 cm KeepFirst; drop a middle point whose four tangents are within 5 deg of the
     chord), then three tests in this order, each failure in its own list: 4 points; every turn (the control
     points' own yaws, `Splines_CalculateAngleToNextPoint`: yaw_i - yaw_(i-1), folded by `trunc(d / 180) x -360`)
     equal to 90 within 1e-8 (`AttributeFilter` Equal on doubles); longest / shortest side < 2;
   - `FilterDataByAttribute_0` / `1` (`@data.MaxHeight` > 2500 / 3500, Greater);
   - medium: `Subgraph_38 Write_Noise` (Set: a new height uniform in 2500..7000, Python's draw, 3.1) then
     `AttributeMathsOp_2` x 2; large: `AttributeMathsOp_1` x 1.3 -> `Loop_2` / `Loop_1 AssignBuildingShape`.
   - The rest, to `Assign_CitySampleBuildings` in `Branch_*DistrictDebug`'s input order: the small ones as
     POLYGONS, then the square test's rejects (count, angle, ratio -- `Gather_0`'s order), then the low squares,
     as cleaned splines.
7. **The building nodes** (native, kept): `@data.MaxHeight` written onto every stream by a `CopyAttributes` adapter
   (N:N); `SpawnMeshes` true (a Python ParamSet: officially `NOT Partitioned`, and `Partitioned` is false);
   `CollisionGeometry` sends the levelled footprints (pre-split) to `Loop_5` / `4` / `3` (4.3).
8. **The rooftops** (`s11_buildings_rooftops`) -- `Gather_6` / `Gather_3` (`SetComplexBuildings` footprints first,
   then `Assign_CitySampleBuildings` rooftops), `Tag_*Rooftops`, `Gather_4`, `Branch_3` Output A, then the chain
   `Subgraph_4` .. `Subgraph_19` (`Filter_RandomChoice`, one Bernoulli per rooftop, ratios 1/13 .. 1/2, Python's
   draws) to the thirteen kept rooftop meshes, the last Unselected to `Subgraph_31`. Every rooftop is forwarded as
   the building node's own spline (`FORWARD_SPLINES`, new; stage 12 reads their last bits, 6.5).

Surface: 176 official nodes, 97 computation by the brief. In Python: 94 of the 97 (incl. 18 named reroute usages,
6 reroute declarations and 6 plain reroutes that became edges); the primitive internals behind them --
`Write_DistanceFrom` (106 + 9 nodes), `Filter_Areas_within_Areas` (9 + 18), `FilterSquareShapes` (33 + 14),
`Transform_Project` (129), `Transform_Level` (6), `Filter_Areas_BySize` (11), `Filter_RandomChoice`, `Write_Noise`
(34) -- are ported step by step above. Native: the three texture writes (4.1).

## 3. Deliberate differences

1. **New random numbers** (spec E2): `Write_Noise`'s 16 medium heights (`Draws.noise`) and the rooftops' material
   chain (`Draws.keep`). The oracle (`s11_buildings.ORACLE_ENV`) substitutes the official noise (6.4).
2. **No partition, no debug**: `Branch_0..6`, `Branch_9..11`, the three `NOT Partitioned`, the spawn-actor loops
   (`Loop_13/19/21`), the planar-mesh-actor loops (`Loop_0/18/20`) and the debug branches and extrudes drop.
   `Loop_0/18/20` are therefore not kept: they run only with `Partitioned` (the generated brief lists them as
   dropped; the 23 kept generation nodes are the three Assign, thirteen meshes, two AssignBuildingShape, two
   SetComplexBuildings and three collision loops).
3. **The collision loops are gated by `CollisionGeometry` alone** (officially also by `Partitioned`, which drops):
   with the shipped false, nothing reaches them, as officially.
4. **Tags**: the footprints carry their read tags less Selected / Unselected (the building nodes drop input
   tags); the rooftops carry the building node's tags plus the class tag, as officially.

## 4. What could not be reproduced, and what was done instead

1. **The texture read stays native** (spec 4.3). `Write_Attribute_fromTexture`'s CoreProcess samples
   `/PCGPrimitives/Materials/Textures/T_Noises_Grunge_4k_` (`GetTextureData_0`, `TextureTransform` scale 100 000,
   Red, `bUseAdvancedTiling`) at every vertex (`ToPoint_0`), remaps the colour to [`RemapValueOutLow`,
   `RemapValueOutHigh`] and averages it into `@data.MaxHeight`. Pure Python cannot read the pixels; the texture
   EXISTS in this project (no `could not be loaded`, unlike stage 13's `T_CloudNoise_4k`, trap 66), so the three
   writes run natively and their output is real.
2. **`@data.MaxHeight` crosses each Python boundary through a native adapter** (stage 10's precedent): a Python
   node can neither read nor write a data-domain attribute in this build (probed: `PCGMetadata`'s domain handles
   and the `*OnDomain` accessors are not callable from Python). In: `ExtractAttribute` (`@data.MaxHeight`, one
   param per footprint, the footprints' order). Out: `CopyAttributes` (Source = the stream's `*Heights` params,
   `MaxHeight` -> `@data.MaxHeight`, N:N), one per stream, eight in all.
3. **Heights: last-bit differences on 11 of 82 HighRise footprints.** The sample positions match the engine's to
   ~1e-11 cm (local evaluation plus translation), the per-vertex remapped distances to 6.2e-15; the target point
   `PCGDistance` uses is the centre of the sample's transformed box (`FBox::TransformBy` of the sample's own
   rotation), not its location, which this port does not rebuild. The heights the building nodes receive differ
   from the official by <= 5.8e-16 relative on 2 medium and 9 large footprints (and 2 large complex ones); every
   other bit is equal (6.2).
4. **Control-point yaws of degenerate vertices.** The input lots carry duplicated vertices; at a zero-length
   segment the engine's rotation is the identity, at a 1e-11 cm one it is the stored local direction, which the
   port can only approximate from the world vertices (the stored local ring is not readable). Yaws match to
   2.3e-13 deg elsewhere (2.4e-9 on near-zero large segments). The building nodes read positions; with the
   official draws the slim graph reproduces the official instance for instance (6.4).
5. **Linear-spline tangents.** The official levelled splines keep the projection's tangents (with the terrain's z
   deltas) because `Transform_Level` moves only positions; the port writes linear control points and the engine
   derives the tangents from the levelled positions. Linear segments ignore tangents for position and length.

## 5. Corrections to the brief

1. **"every building footprint's height attribute is inside its class's range"**: only the texture height is. The
   HighRise factor reaches 5 (the large class reaches 33 555 cm against a 7 000 cm maximum), the complex shapes
   x 2 / x 1.3 and `Write_Noise` replaces the medium ones with 2500..7000 before the x 2. The check asserts the
   texture heights' range and the factor's direction instead.
2. **"clamped to the class range"**: there is no clamp in the official graph.
3. **"HighRise distance/multiplier"**: the factor is the AVERAGE of the remapped vertex distances (the node title
   says Max), and it grows with the distance from the zone's EDGE (the zones' outlines are sampled), 1 at the
   class's least deep vertex, 5 at its deepest.
4. **"each input footprint produces exactly one rooftop polygon"**: the rooftops are the native nodes' (the 77
   small footprints give 74 rooftops; the 180 medium give 203, the complex shapes several each); what holds is that
   every footprint reaches exactly one building node, which the check asserts. "the rooftop polygons partition their footprints"
   cannot be checked in Python: the rooftops are generated natively.
5. **"Write_Attribute_fromTexture stays native if the texture sampling cannot be called"**: it cannot; done (4.1).
6. **"the rooftop mesh actor loops" (Loop_0/18/20)**: Partitioned-only, dropped (3.2).

## 7. Carry

- **Stage 12** reads the rooftops by tag; with the splines forwarded it reproduces the official exactly (6.5).
- **`geo.frames`** reproduces `CreatePolygon2D`'s frame and stored ring, `ToPoint`'s recomputed vertices and the
  spline distance sampler bit for bit on this level; the stages that rebuild polygons through the engine (9, 10,
  13, 14: s10.md 4.1, trap 68) can use it instead of world-coordinate approximations.
- **The texture write's input is a polygon of the stage-9 volume, forwarded**: a port of stage 9 that rewrote
  its footprints would change their frames, hence the texture sample points' last bits, hence the heights.
- **Not exercised on this level**: `CollisionGeometry` (false here; the loops would write actors and assets under
  `/CitySamplePCG/Levels/Collision`, so it was not switched on), `ComplexBuildingShapes` false (the levelled
  footprints straight to the building nodes; tested offline only).
